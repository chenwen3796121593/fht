## 二、板块资金流 TOP 空白 —— 根因修复

### 问题现象
主页「板块资金流入 / 流出 TOP」长期无数据，卡片一直显示「加载中…」。

### 根因（两层叠加，缺一不可）

**根因 1：`URLSearchParams` 把 `+` 转义了**

东财行业板块的市场筛选参数是 `fs=m:90+t:2`，其中的 `+` 是东财的**字面语法**。
一旦用 `URLSearchParams` 拼接，`+` 会被编码为 `%2B`，东财按字面解析该参数 → **返回空 diff**。

> 结论：**此接口必须手工拼接 query string，禁止使用 `URLSearchParams`。**

**根因 2：域名用错**

历史代码使用 `push2.eastmoney.com`，该域名存在两个问题：
- Cloudflare 边缘出口访问返回 **502**（服务端代理走不通）
- 对客户端存在 IP 封禁风险

**根因 3（部署时新发现）：`po` 参数重复导致流出榜恒空**

基础 query 串里已经包含 `po=1`，代码在发流出请求时又追加了 `&po=0`。
实测确认：**东财只认第一个 `po`** —— 所谓"流出请求"实际返回的是流入榜，
前端再按 `netFlow < 0` 过滤后，「流出 TOP」**必然为空**。

### 解决方案（当前架构）

```
浏览器（国内网络）
   └─ fetch 直连东财 push2delay/push2ex
        └─ Service Worker (public/sw.js) 白名单透传（第二道防线）
```

不经过后端 `/api`。因为**东财会回显 Origin**，CORS 校验通过，浏览器裸调即可读取响应体，
这也是本方案不需要服务端代理的原因。

**接口配方**

```
https://push2delay.eastmoney.com/api/qt/clist/get
  ?pn=1&pz=40&np=1&fltt=2&invt=2
  &fid=f62
  &fs=m:90+t:2
  &fields=f12,f14,f62,f184
  &po=1        # 降序 → 资金流入 TOP
  &po=0        # 升序 → 资金流出 TOP
```

| 字段 | 含义 |
|------|------|
| `f14` | 板块名称 |
| `f62` | 主力净流入（单位：元） |
| `f184` | 涨跌幅 |

**域名策略**

- 主用：`push2delay.eastmoney.com`
- 备用：`push2ex.eastmoney.com`（主域失败时自动回退）

**⚠️ 禁用域名清单（历史事故，勿再使用）**

| 域名 | 问题 |
|------|------|
| `push2.eastmoney.com` | CF 边缘 502 + 客户端封 IP |
| `hq.sinajs.cn` | 无 CORS |
| `push2his.eastmoney.com` | 响应体为空 |

**节流策略**

前端 `throttledFetch` 实现 **25 秒最小间隔 + 在途请求去重（`inFlight` 标志）**。
Service Worker 仅作为第二道防线，不承担节流职责。

**空状态处理（三态）**

| 状态 | 文案 |
|------|------|
| 请求中 | 加载中… |
| 上游返回空 diff（收盘清算时段常见） | 上游本次未返回任何行业板块资金数据 |
| 请求失败 | 暂时无法获取数据，请稍后重试 |

收盘清算时段返回空 diff 属正常现象，**按空状态展示，不作为错误上报**。

### 涉及文件

| 文件 | 操作 |
|------|------|
| `public/sw.js` | **新增** —— 白名单仅放行 `push2delay` / `push2ex` 两域名 |
| `public/service-worker.js` | **删除** —— 旧 SW，逻辑已被 `sw.js` 取代 |
| `src/main.jsx` | 注册路径由 `/service-worker.js` 改为 `/sw.js` |
| `src/pages/HomePage.jsx` | `SectorFlow` 组件重写 |
| `functions/api/flow.js` | **删除** —— 空桩，已无调用方 |

### 上线注意事项

新 SW 已设置 `skipWaiting()` + `clients.claim()`，缓存版本升至 `v6`（激活时自动清除 v5 旧缓存）。
但旧 `/service-worker.js` 在 CF 边缘仍有缓存残留，**用户需硬刷新一次**完成 SW 切换。

## 三、贵金属子页重设计

### 页面结构

改为上下两栏布局：

- **上栏**：伦敦黄金 K 线图（`GoldKline` 组件）
- **下栏**：8 品种行情表（单一表格，左侧品种名、右侧价格）

品种清单：黄金、伦敦黄金、白银、伦敦白银、铂金、美铂金、钯金、美钯金。
国际品种行若无 tick 数据仍会被过滤，不展示脏数据。

「金友圈」的现货黄金入口点击后直达该图表页。

### K 线数据源（国内可达性优先）

后端 `functions/api/gold-kline.js` 按周期分流：

| 周期 | 数据源 | 说明 |
|------|--------|------|
| 1 小时 / 4 小时 | Kraken `XAUTUSD` OHLC | 经 CF Functions 代理 |
| 日线 / 周线 | 新浪全球期货 `XAU` 日线 | 国内直连可达 |
| 月线 | 由新浪日线聚合生成 | — |

结果写入 KV 缓存。

> **背景**：CF Functions 出口对 Binance / Bybit / Yahoo / 东财 push2 均不可达（403 / 502）；
> 实测可用的有 Kraken、`stock2.finance.sina.com.cn`、腾讯、`x-quote.cls.cn`。

### 图表参考线

图上叠加 4 条参考线：

| 参考线 | 样式 | 取值 |
|--------|------|------|
| 阻力 | 红色虚线 | 当前窗口最高价 |
| 支撑 | 绿色虚线 | 当前窗口最低价 |
| 枢轴 | 金色点线 | (H + L + C) / 3 |
| 现价 | 灰色长虚线 | 最新价 |

### lightweight-charts v5 踩坑记录

本项目使用 **lightweight-charts v5**，与 v4 存在 API 差异，修复过程踩了三个坑：

1. **参考线不显示** —— 图表创建分支里的 `return` 提前跳过了绘制逻辑。
   → 拆成两个 `useEffect`：创建只执行一次，数据与参考线每次重绘。

2. **切换周期后参考线堆叠** —— 空数据分支直接 `return`，未清理旧线。
   → 改为**无条件先清旧线，再绘新线**。

3. **清理无效，参考线仍重复** —— v5 的 `IPriceLine` **没有 `.remove()` 方法**，
   调用 `pl.remove()` 抛错后被 `try/catch` 静默吞掉。
   → 必须改用 `series.removePriceLine(pl)`。
